# Session log — 2026-10-07: Queue, notification, and menu fixes

Branch: `android-support`

All fixes below were reproduced, patched, and re-verified end-to-end on the
Android emulator (`emulator-5554`, debug build) against the local backend on
port 5000.

## Fixes

### 1. Single-track queue: skip buttons were a no-op

**Symptom:** With one track in the queue, Next/Prev appeared disabled
(`hasNext`/`hasPrevious` false) and did nothing.

**Fix:**
- `lib/features/player/player_page.dart`, `lib/features/player/mini_player.dart`
  — Next/Prev are no longer gated on `hasNext`/`hasPrevious`; the buttons are
  always active.
- `lib/features/player/player_controller.dart` — `seekToNext()` falls back to
  `_autoplayRelated()` when the player has no next item (same fill used when
  the queue ends naturally).
- `lib/audio_handler.dart` — new `onQueueExhausted` callback (wired to
  `_autoplayRelated` in `_initialize`) so skips from the system notification /
  lock screen also refill the queue. `skipToNext()` calls it and steps into the
  appended tail if the fill only appended.

### 2. Queue title desync after remove/reorder

**Symptom:** Removing a track before the current one, or reordering the queue,
left the old title/artist in the mini player / full player.

**Fix:** `removeFromQueue` and `reorderQueue` now re-sync
`currentTitle`/`currentArtist`/`currentUrl` from the new queue, because the
index stream can fire while the old queue is still in state.

### 3. "See all" on Home playlists did nothing

**Fix:** `lib/main.dart` — the button now runs
`Navigator.pushNamed(context, '/playlist')` (opens the Library page) instead of
an empty `setState`.

### 4. Autoplay died on demo tracks

**Symptom:** When the last played track was a demo seed (no real `videoId`),
`_autoplayRelated` returned early and playback ended silently.

**Fix:** `_autoplayRelated` falls back to `musicApi.getCharts(limit: 10)` when
the radio request fails or returns nothing, de-duplicates against the current
queue, and lets playback end quietly only if both sources fail.

### 5. Double track advance at queue completion

**Symptom:** When the queue finished naturally, ExoPlayer auto-jumped into the
freshly appended track while the fill's explicit seek also advanced — skipping
the first related track.

**Fix:** `_autoplayRelated` pauses the player before appending (freezing the
ended state so the explicit seek is the only step), then seeks and resumes.
Appends were also batched into a single `addAll` timeline change to reduce
media-session/notification churn.

### 6. Stuck media notification after clearing via mini-player X

**Symptom:** Tapping X on the mini player (`stopAndClear`) removed the
notification, but it reappeared stuck a moment later showing the stopped track.

**Root cause:** After `stop()`, just_audio re-emits `currentIndexStream` /
`sequenceStream` for the track that was just stopped. `syncMediaItem` pushed the
same `MediaItem` again → audio_service's `setMetadata` posts
`updateNotification` onto the Java main thread *after* `stop()` already canceled
notification 1124, re-posting it with no way to clear it.

**Fix:** `lib/audio_handler.dart` — `syncMediaItem` keeps `_lastMediaItem` and
skips pushes of the identical item; `loadUrl` seeds the same field.

**Verified scenarios:** direct play → X (absent), replay → present with
title, completion → charts fill → pause → back → X (absent).

### 7. ⋮ menu "Add all to queue" race (queue list vs player desync)

**Symptom:** Adding a 2-track playlist showed "1 track" in the queue list while
the notification displayed the second track.

**Root cause:** The fire-and-forget loop let the first track's `playTrack`
(auto-started when the queue is empty) overwrite state written by later
appends.

**Fix:** `lib/main.dart` — `onSelected` is async and awaits each `addToQueue`
sequentially, with a `mounted` guard before the SnackBar.

## Tooling notes (emulator quirks, not app bugs)

- `adb shell screencap` intermittently returns **stale frames** on this
  dual-display emulator (`EMU_display_0` 1080x2400 + `EMU_display_1`
  1080x2092). Prefer
  `adb exec-out screencap -d <SurfaceFlinger-display-id> -p > out.png` (raw
  redirect via `cmd /c` on Windows) and sanity-check the status-bar clock
  against `adb shell date`.
- `uiautomator dump` fails with `could not get idle state` while media is
  playing — pause first (`input keyevent 85`). Dumps also go stale silently;
  `rm` the old XML before dumping.
- Flutter text is not exposed to `uiautomator` until
  `settings put secure accessibility_enabled 1`; labels then appear in
  `content-desc`.
